# 发布徒步活动 — 业务流程图

## 参与角色（三泳道）

| 泳道 | 角色 |
|------|------|
| 左 | 组织者 |
| 中 | 系统平台 |
| 右 | 管理员 |

## 流程步骤

```
┌──────────────┬──────────────────┬─────────────────┐
│    组织者     │     系统平台      │     管理员       │
├──────────────┼──────────────────┼─────────────────┤
│   ● (开始)   │                  │                 │
│      ↓       │                  │                 │
│  填写活动信息 →  保存活动草稿     │                 │
│              │   [DRAFT]        │                 │
│      ↓       │                  │                 │
│  提交审核    →  更新状态为       │                 │
│              │  PENDING_AUDIT   │                 │
│              │      ↓           │                 │
│              │  通知管理员  ────→  审核活动详情     │
│              │                  │      ↓          │
│              │                  │  ◇ 是否通过？   │
│              │                  │  ↓是      ↓否   │
│              │   更新状态    ←───│─ 通过    驳回   │
│              │      ↓           │                 │
│              │  ◇ 审核结果？     │                 │
│              │  ↓通过    ↓驳回   │                 │
│              │ PUBLISHED REJECTED                 │
│              │    ↓         ↓   │                 │
│  发布成功 ←──│────┘         └──→│ 组织者收到驳回   │
│    ↓         │                  │      ↓          │
│  ◉(结束)     │              ◇ 是否重新提交？       │
│              │              ↓是        ↓否        │
│              │           修改活动     ◉(结束)      │
│              │          (回到"提交审核")           │
└──────────────┴──────────────────┴─────────────────┘
```

## 状态流转

```
DRAFT(0) ──提交审核──→ PENDING_AUDIT(1) ──审核通过──→ PUBLISHED(2)
  ↑                                      │
  └──────── 修改重新提交 ←── REJECTED(6) ←─┘审核驳回
```

## 各节点说明

### 组织者操作
1. **填写活动信息**：标题、难度、时间地点、报名设置、关联路线与签到点
2. **提交审核**：确认无误后将草稿提交审核
3. **收到驳回后**：可修改重新提交，或放弃发布

### 系统平台处理
1. **保存活动草稿**：校验并持久化，状态设为 DRAFT
2. **更新状态**：提交审核时改为 PENDING_AUDIT，审核后改为 PUBLISHED 或 REJECTED
3. **消息通知**：审核提交时通知管理员，审核完成后通知组织者

### 管理员操作
1. **审核活动详情**：查看活动完整信息
2. **通过或驳回**：通过则发布，驳回需填写原因
