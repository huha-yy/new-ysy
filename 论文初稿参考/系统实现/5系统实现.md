# 5 系统实现

本章详细阐述系统主要功能的实现过程，包括系统界面展示、实现原理和关键代码。系统基于Spring Boot后端框架和React前端框架开发，采用B/S架构，用户可通过浏览器访问系统各功能模块。

## 5.1 活动管理功能实现

### （1）系统界面

组织者登录系统后，可进入活动管理页面发起活动创建。活动创建采用分步表单形式，分为基本信息、时间地点、报名设置、路线配置四个步骤。组织者依次填写活动标题、难度等级、封面图片、活动描述、活动时间、报名截止时间、最大参与人数、关联路线等信息。信息填写完成后点击"保存草稿"按钮，活动将以草稿状态保存。组织者在"我的活动"页面可查看所有活动，点击"提交审核"按钮将活动提交给管理员审批。管理员在审核页面查看活动详情后，可选择通过或驳回。活动审核通过后自动发布，对所有用户可见。如图5-1所示。

### （2）实现原理

活动管理功能采用分层架构实现。前端使用React框架构建用户界面，通过Axios发送HTTP请求与后端交互。后端采用Spring Boot框架，Controller层接收请求并调用Service层处理业务逻辑，Service层通过MyBatis-Plus操作数据库。

活动实体采用状态机管理模式，定义了7种状态：草稿（0）、待审核（1）、已发布（2）、进行中（3）、已结束（4）、已取消（5）、已驳回（6）。状态流转遵循严格的业务规则：草稿状态可提交审核，待审核状态可审核通过或驳回，已发布状态可开始或取消，进行中状态可结束。

创建活动时，系统首先校验用户角色是否为组织者或管理员，然后校验关联的路线是否存在。校验通过后，构建Activity实体对象，设置初始状态为草稿，通过MyBatis-Plus的insert方法持久化到数据库。提交审核时，系统更新活动状态为待审核，并通过消息服务通知管理员。审核活动时，系统根据审核结果更新状态为已发布或已驳回，同时记录审核人和审核时间。

活动创建的核心实现如下：

```java
// ActivityServiceImpl.java
public Long createActivity(ActivityCreateDTO dto) {
    // 校验用户角色
    User user = userMapper.selectById(SecurityUtils.getCurrentUserId());
    if (user.getRole() != 1 && user.getRole() != 2) {
        throw new BusinessException("无权限创建活动");
    }
    // 校验路线是否存在
    Route route = routeMapper.selectById(dto.getRouteId());
    if (route == null) {
        throw new BusinessException("路线不存在");
    }
    // 构建活动实体
    Activity activity = new Activity();
    BeanUtils.copyProperties(dto, activity);
    activity.setOrganizerId(user.getId());
    activity.setStatus(0); // 草稿状态
    activity.setCurrentParticipants(0);
    activityMapper.insert(activity);
    return activity.getId();
}
```

活动审核的核心实现如下：

```java
// ActivityServiceImpl.java
public void auditActivity(Long id, ActivityAuditDTO dto) {
    Activity activity = activityMapper.selectById(id);
    if (activity.getStatus() != 1) {
        throw new BusinessException("活动状态不允许审核");
    }
    if (dto.getApproved()) {
        activity.setStatus(2); // 已发布
    } else {
        activity.setStatus(6); // 已驳回
        activity.setRejectReason(dto.getRejectReason());
    }

    activity.setAuditTime(LocalDateTime.now());
    activityMapper.updateById(activity);
}
```

## 5.2 报名管理功能实现

### （1）系统界面

用户在活动详情页点击"立即报名"按钮后，系统弹出报名表单对话框。表单包含报名备注、紧急联系人、紧急联系电话三个输入项，以及装备确认和健康确认两个复选框。用户填写完成后点击"确认报名"按钮提交申请。组织者在"报名管理"页面可查看所有报名记录，支持按状态筛选（待审核、已通过、已驳回、候补）。组织者点击单条记录的"通过"或"驳回"按钮进行审核，也可点击"批量通过"一次性通过所有待审核记录。用户在"我的报名"页面可查看自己的报名状态，并可在活动开始前取消报名。如图5-2所示。

### （2）实现原理

报名管理功能的核心是容量控制和状态流转。系统维护活动的当前参与人数字段，用户提交报名时，系统先查询活动的最大参与人数和当前参与人数。若当前人数小于最大人数，报名状态设为待审核（0）；若已满员，报名状态设为候补（3）并分配排队号。

报名实体定义了6种状态：待审核（0）、已通过（1）、已驳回（2）、候补（3）、已取消（4）、缺席（5）。审核通过时，系统将报名状态更新为已通过，同时将活动的当前参与人数加1。审核驳回时，仅更新报名状态和驳回原因。用户取消报名时，若原状态为已通过，系统需将活动的当前参与人数减1。

系统通过唯一约束防止重复报名，同一用户对同一活动只能有一条有效的报名记录（待审核、已通过、候补状态）。已取消、已驳回、缺席的记录允许用户重新报名。

### （3）关键代码

提交报名的核心实现如下：

```java
// RegistrationServiceImpl.java
public Long submitRegistration(RegistrationCreateDTO dto) {
    Long userId = SecurityUtils.getCurrentUserId();
    // 校验活动状态和时间
    Activity activity = activityMapper.selectById(dto.getActivityId());
    if (activity.getStatus() != 2 && activity.getStatus() != 3) {
        throw new BusinessException("活动未开放报名");
    }
    // 校验是否重复报名
    LambdaQueryWrapper<Registration> wrapper = new LambdaQueryWrapper<>();
    wrapper.eq(Registration::getUserId, userId)
           .eq(Registration::getActivityId, dto.getActivityId())
           .in(Registration::getStatus, 0, 1, 3);
    if (registrationMapper.selectCount(wrapper) > 0) {
        throw new BusinessException("您已报名该活动");
    }
    // 判断是否满员，设置状态
    Registration registration = new Registration();
    registration.setUserId(userId);
    registration.setActivityId(dto.getActivityId());
    if (activity.getCurrentParticipants() >= activity.getMaxParticipants()) {
        registration.setStatus(3); // 候补
        registration.setQueueNumber(getNextQueueNumber());
    } else {
        registration.setStatus(0); // 待审核
    }
    registrationMapper.insert(registration);
    return registration.getId();
}
```

审核报名的核心实现如下：

```java
// RegistrationServiceImpl.java
public void auditRegistration(Long id, RegistrationAuditDTO dto) {
    Registration registration = registrationMapper.selectById(id);
    if (registration.getStatus() != 0 && registration.getStatus() != 3) {
        throw new BusinessException("报名状态不允许审核");
    }
    if (dto.getApproved()) {
        registration.setStatus(1); // 已通过
        // 活动参与人数+1
        activityMapper.incrementParticipants(registration.getActivityId());
    } else {
        registration.setStatus(2); // 已驳回
        registration.setRejectReason(dto.getRejectReason());
    }
    registration.setAuditBy(SecurityUtils.getCurrentUserId());
    registration.setAuditTime(LocalDateTime.now());
    registrationMapper.updateById(registration);
}
```

## 5.3 GPS签到功能实现

### （1）系统界面

用户进入签到页面后，系统自动请求浏览器定位权限并获取当前位置。页面顶部显示签到进度条，以百分比和"已完成数/总数"格式展示。主体区域左侧为地图组件，以标记点形式显示所有签到点位置，蓝色圆点表示用户当前位置；右侧为签到点列表，每个签到点项显示序号、名称、与用户的距离、有效半径和签到按钮。当用户进入签到点有效范围内时，签到按钮变为可点击状态，点击后完成签到，该签到点显示绿色"已签到"标签和签到时间。所有签到点完成后，页面显示庆祝动画。如图5-3所示。

### （2）实现原理

GPS签到功能的核心是位置验证。前端通过浏览器Geolocation API获取用户当前位置（WGS84坐标系），经坐标转换为GCJ02坐标系后在地图上显示。用户点击签到按钮时，前端将用户坐标和签到点ID发送到后端。

后端收到签到请求后，首先校验用户的报名状态是否为已通过，活动状态是否为进行中。校验通过后，系统计算用户位置与签到点的距离，使用Haversine公式计算两个经纬度坐标间的球面距离。若距离小于等于签到点的有效半径（默认100米），签到成功，系统根据签到时间判断是否迟到（超过预计到达时间+10分钟为迟到），然后生成签到记录保存到数据库。若距离超出有效范围，返回签到失败提示。

系统还实现了轨迹记录功能，前端定时采集用户位置数据并批量上报到后端，后端存储轨迹记录的同时触发偏离检测。偏离检测计算用户位置与路线所有路点的最小距离，若超过阈值则生成预警事件通知组织者。

### （3）关键代码

GPS签到的核心实现如下：

```java
// CheckInServiceImpl.java
public void performCheckIn(Long activityId, CheckInDTO dto) {
    Long userId = SecurityUtils.getCurrentUserId();
    // 校验报名状态
    Registration registration = registrationMapper.selectOne(
        new LambdaQueryWrapper<Registration>()
            .eq(Registration::getUserId, userId)
            .eq(Registration::getActivityId, activityId)
            .eq(Registration::getStatus, 1));
    if (registration == null) {
        throw new BusinessException("您未报名该活动");
    }
    // 获取签到点信息
    Checkpoint checkpoint = checkpointMapper.selectById(dto.getCheckpointId());
    // 计算距离
    double distance = GeoUtils.calculateDistance(
        dto.getLatitude(), dto.getLongitude(),
        checkpoint.getLatitude(), checkpoint.getLongitude());
    if (distance > checkpoint.getRadius()) {
        throw new BusinessException("不在签到范围内，距离：" + Math.round(distance) + "米");
    }
    // 判断是否迟到
    int status = 1; // 正常
    if (checkpoint.getExpectedArriveMinutes() != null) {
        LocalDateTime activityStart = LocalDateTime.of(
            activity.getActivityDate(), activity.getStartTime());
        LocalDateTime expectedTime = activityStart
            .plusMinutes(checkpoint.getExpectedArriveMinutes());
        if (LocalDateTime.now().isAfter(expectedTime.plusMinutes(10))) {
            status = 2; // 迟到
        }
    }
    // 保存签到记录
    CheckInRecord record = new CheckInRecord();
    record.setUserId(userId);
    record.setActivityId(activityId);
    record.setCheckpointId(dto.getCheckpointId());
    record.setCheckInTime(LocalDateTime.now());
    record.setStatus(status);
    record.setDistanceToCheckpoint(distance);
    checkInRecordMapper.insert(record);
}
```

距离计算工具方法：

```java
// GeoUtils.java
public static double calculateDistance(double lat1, double lng1, double lat2, double lng2) {
    double earthRadius = 6371000; // 地球半径（米）
    double dLat = Math.toRadians(lat2 - lat1);
    double dLng = Math.toRadians(lng2 - lng1);
    double a = Math.sin(dLat / 2) * Math.sin(dLat / 2) +
               Math.cos(Math.toRadians(lat1)) * Math.cos(Math.toRadians(lat2)) *
               Math.sin(dLng / 2) * Math.sin(dLng / 2);
    double c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a));
    return earthRadius * c;
}
```

## 5.4 本章小结

本章详细阐述了户外徒步活动管理系统三个核心功能的实现过程。活动管理功能采用分层架构设计，通过状态机模式管理活动生命周期，实现了从草稿创建、提交审核、管理员审核到发布执行的完整业务流程。报名管理功能基于容量控制机制，通过状态流转和唯一约束实现了报名、审核、候补、取消等业务场景，保证了活动参与人数的准确性。GPS签到功能基于浏览器Geolocation API获取用户位置，通过Haversine公式计算距离进行签到范围验证，同时实现了轨迹自动记录和偏离预警功能。通过本章的实现，系统的核心业务功能已全部完成，系统架构清晰，代码结构合理，满足设计目标和使用需求。
