# GPS签到用例描述

| 字段 | 内容 |
|------|------|
| **用例名称** | GPS签到 |
| **用例描述** | 参与者到达活动路线的签到点后，通过提交GPS位置信息完成签到。系统验证位置是否在有效范围内，记录签到时间和状态（正常/迟到）。 |
| **执行者** | 参与者（已报名通过的活动参与者） |
| **前置条件** | 1. 参与者已登录系统<br>2. 参与者报名该活动且审核通过（报名状态=APPROVED）<br>3. 活动状态为进行中（IN_PROGRESS）<br>4. 参与者未在该签到点签过到<br>5. 参与者已到达签到点附近 |
| **后置条件** | 1. 生成签到记录（CheckInRecord）<br>2. 签到记录包含位置、距离、签到时间、状态<br>3. 若签到成功，系统通知组织者<br>4. 若签到失败，提示参与者重新定位 |
| **主流程描述** | 1. 参与者打开活动签到页面<br>2. 系统获取参与者当前GPS位置<br>3. 系统查询该活动的所有签到点信息<br>4. 参与者选择要签到的检查点<br>5. 系统计算参与者位置与签到点的距离<br>6. 系统判断距离是否≤有效半径（默认100米）<br>7. 距离符合要求，系统记录签到信息<br>8. 系统判断签到时间是否超过预计到达时间+10分钟<br>9. 若未超时，签到状态=正常；若超时，签到状态=迟到<br>10. 系统保存签到记录到数据库<br>11. 系统返回签到成功提示<br>12. 参与者查看签到成功确认 |
| **分支流程描述** | **分支1：重复签到**<br>- 在第4步，若参与者已在该签到点签过到<br>- 系统提示"您已在该检查点签到过"<br>- 用例结束<br><br>**分支2：签到点不存在**<br>- 在第4步，若选择的签到点不存在或已删除<br>- 系统提示"签到点信息已更新，请刷新重试"<br>- 用例结束 |
| **异常流程描述** | **异常1：距离超出范围**<br>- 在第6步，若距离 > 有效半径<br>- 系统提示"您距离签到点过远（当前距离：XXX米），请靠近后重试"<br>- 显示签到点位置和参与者当前位置<br>- 参与者重新定位后可重新发起签到<br>- 用例回到第2步<br><br>**异常2：GPS定位失败**<br>- 在第2步，若无法获取GPS位置<br>- 系统提示"定位失败，请检查GPS权限和网络连接"<br>- 参与者可重试或手动输入位置<br>- 用例结束<br><br>**异常3：活动已结束**<br>- 在第1步，若活动状态已变为ENDED<br>- 系统提示"活动已结束，无法签到"<br>- 用例结束<br><br>**异常4：报名状态异常**<br>- 在前置条件检查时，若报名状态不是APPROVED<br>- 系统提示"您的报名未通过审核，无法签到"<br>- 用例结束 |

## 补充说明

### 数据模型
- **CheckInRecord**：userId, activityId, checkpointId, checkInTime, latitude, longitude, distanceToCheckpoint, status(1=正常/2=迟到/3=补签)

### 关键业务规则
- 有效半径默认100米，可由组织者配置
- 迟到判定：签到时间 > 预计到达时间 + 10分钟
- 同一用户同一签到点只能签到一次
- 签到成功后，组织者监控面板实时更新该参与者的签到进度
