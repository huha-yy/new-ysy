# 提交报名申请用例描述

| 字段 | 内容 |
|------|------|
| **用例名称** | 提交报名申请 |
| **用例描述** | 已登录用户在活动详情页填写紧急联系人等信息，提交报名申请。系统校验报名条件后创建报名记录，若名额未满则进入待审核状态，若名额已满则进入候补队列。 |
| **执行者** | 注册用户（已登录用户） |
| **前置条件** | 1. 用户已登录系统<br>2. 活动状态为已发布(2)或进行中(3)<br>3. 当前时间未超过报名截止时间<br>4. 用户未在该活动有有效的报名记录（待审核/已通过/候补）<br>5. 用户已到达活动详情页 |
| **后置条件** | 1. 生成报名记录（Registration）<br>2. 若名额未满，报名状态=PENDING(待审核)<br>3. 若名额已满，报名状态=WAITING(候补)，分配排队号<br>4. 系统通知组织者有新报名<br>5. 用户跳转至"我的报名"页面 |
| **主流程描述** | 1. 用户在活动详情页点击"立即报名"按钮<br>2. 系统弹出报名表单对话框<br>3. 用户填写紧急联系人姓名（必填）<br>4. 用户填写紧急联系人电话（必填，校验手机号格式）<br>5. 用户填写报名备注（选填）<br>6. 用户勾选"我确认已准备所需装备"复选框<br>7. 用户勾选"我确认身体健康，适合参加此次活动"复选框<br>8. 用户点击"提交报名"按钮<br>9. 系统校验表单必填字段<br>10. 系统校验用户是否有重复报名<br>11. 系统校验报名截止时间<br>12. 系统判断活动名额是否已满<br>13. 名额未满，系统创建报名记录（状态=PENDING）<br>14. 系统保存报名记录到数据库<br>15. 系统发送站内消息通知组织者<br>16. 系统提示"报名成功，请等待组织者审核"<br>17. 页面跳转至"我的报名"页面 |
| **分支流程描述** | **分支1：名额已满，进入候补**<br>- 在第12步，若当前参与人数≥最大参与人数<br>- 系统计算候补排队号（当前最大排队号+1）<br>- 系统创建报名记录（状态=WAITING，queueNumber=排队号）<br>- 系统提示"活动名额已满，您已进入候补队列，排队号：X"<br>- 后续流程与主流程第14-17步相同<br><br>**分支2：之前有已取消/已驳回的报名记录**<br>- 在第10步，系统检测到用户之前有已取消/已驳回/缺席的报名<br>- 系统自动删除旧报名记录<br>- 允许用户重新报名<br>- 用例继续执行第12步 |
| **异常流程描述** | **异常1：必填字段为空**<br>- 在第9步，若紧急联系人或电话为空<br>- 系统提示"请填写紧急联系人信息"<br>- 用户补充填写<br>- 用例回到第8步<br><br>**异常2：手机号格式不正确**<br>- 在第9步，若手机号格式不正确（非11位数字）<br>- 系统提示"请输入正确的手机号"<br>- 用户修改手机号<br>- 用例回到第8步<br><br>**异常3：未勾选确认框**<br>- 在第9步，若用户未勾选任一确认框<br>- 系统提示"请确认装备和健康状态"<br>- 用户勾选确认框<br>- 用例回到第8步<br><br>**异常4：重复报名**<br>- 在第10步，若用户已有待审核/已通过/候补的报名<br>- 系统提示"您已报名该活动，请勿重复报名"<br>- 对话框关闭<br>- 用例结束<br><br>**异常5：报名截止时间已过**<br>- 在第11步，若当前时间>报名截止时间<br>- 系统提示"报名已截止"<br>- 对话框关闭<br>- 活动详情页"立即报名"按钮置灰<br>- 用例结束<br><br>**异常6：活动已取消**<br>- 在第12步之前，若活动被取消<br>- 系统提示"活动已取消，无法报名"<br>- 对话框关闭<br>- 用例结束 |

## 补充说明

### 数据模型
- **Registration**：userId, activityId, status, queueNumber, remark, emergencyContactName, emergencyContactPhone, auditBy, auditTime, cancelTime, createTime, updateTime

### 状态流转
```
提交报名 → PENDING(0) ──审核通过──→ APPROVED(1)
        → WAITING(3) ──审核通过──→ APPROVED(1)

PENDING/WAITING ──审核驳回──→ REJECTED(2)
PENDING/APPROVED/WAITING ──用户取消──→ CANCELLED(4)
```

### 关键业务规则
- 紧急联系人电话必须为11位有效手机号
- 两个确认框必须全部勾选
- 同一用户同一活动只能有一个有效报名（PENDING/APPROVED/WAITING）
- 已取消/已驳回/缺席的报名允许重新报名（旧记录删除）
- 名额判定：currentParticipants >= maxParticipants 视为已满
- 候补排队号全局递增（不按活动区分）
