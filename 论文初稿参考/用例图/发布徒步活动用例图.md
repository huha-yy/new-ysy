# 发布徒步活动 — 用例图

## 参与者（Actor）

| 参与者 | 说明 |
|--------|------|
| 组织者（Organizer） | 创建和管理徒步活动的用户，角色值 = 1 |
| 管理员（Admin） | 审核活动的系统管理员，角色值 = 2 |

## 用例清单

| 编号 | 用例名称 | 参与者 | 关系 | 说明 |
|------|---------|--------|------|------|
| UC-01 | 创建活动草稿 | 组织者 | — | 填写完整信息后保存为 DRAFT 状态 |
| UC-02 | 填写活动信息 | 组织者 | «include» ← UC-01 | 设置标题、难度、时间、报名配置等 |
| UC-03 | 选择关联路线 | 组织者 | «include» ← UC-01 | 从已有路线中选择或自定义路线 |
| UC-04 | 配置签到检查点 | 组织者 | «include» ← UC-01 | 设置 GPS 签到点，可从路线自动继承 |
| UC-05 | 提交活动审核 | 组织者 | — | 将 DRAFT/REJECTED 活动提交为 PENDING_AUDIT |
| UC-06 | 审核活动 | 管理员 | — | 查看待审核活动详情，做出审批决定 |
| UC-07 | 通过并发布活动 | 管理员 | «extend» ← UC-06 | 审核通过，状态变为 PUBLISHED |
| UC-08 | 驳回活动 | 管理员 | «extend» ← UC-06 | 审核不通过，填写驳回原因，状态变为 REJECTED |
| UC-09 | 修改被驳回活动 | 组织者 | «extend» ← UC-08 | 收到驳回后修改信息，可重新提交审核 |

## 用例关系说明

### «include» 关系（必须包含）
- **创建活动草稿** include **填写活动信息**：创建活动必须填写基本信息
- **创建活动草稿** include **选择关联路线**：创建活动必须关联一条路线
- **创建活动草稿** include **配置签到检查点**：创建活动必须设置签到点

### «extend» 关系（条件扩展）
- **审核活动** extend **通过并发布活动**：审核结果为通过时触发
- **审核活动** extend **驳回活动**：审核结果为不通过时触发
- **驳回活动** extend **修改被驳回活动**：组织者收到驳回后可选择修改重提交

## 关键用例描述

### UC-01 创建活动草稿

| 项目 | 内容 |
|------|------|
| 用例名称 | 创建活动草稿 |
| 参与者 | 组织者 |
| 前置条件 | 用户已登录且角色为组织者(1)或管理员(2) |
| 后置条件 | 活动以 DRAFT(0) 状态保存到数据库 |
| 基本流程 | 1. 组织者进入活动创建页面 |
|          | 2. 填写活动基本信息（标题、难度、封面、描述） |
|          | 3. 设置活动时间、报名截止时间 |
|          | 4. 选择关联路线 |
|          | 5. 配置报名设置（人数上限、费用、审核方式） |
|          | 6. 配置签到检查点 |
|          | 7. 点击保存，系统校验数据 |
|          | 8. 校验通过，保存为草稿 |
| 异常流程 | 7a. 校验失败，系统返回错误提示，组织者修改后重新提交 |

### UC-05 提交活动审核

| 项目 | 内容 |
|------|------|
| 用例名称 | 提交活动审核 |
| 参与者 | 组织者 |
| 前置条件 | 活动状态为 DRAFT(0) 或 REJECTED(6)，且当前用户为活动创建者 |
| 后置条件 | 活动状态变为 PENDING_AUDIT(1)，管理员收到审核通知 |
| 基本流程 | 1. 组织者在"我的活动"页面找到草稿/被驳回活动 |
|          | 2. 点击"提交审核"按钮 |
|          | 3. 系统验证活动状态和权限 |
|          | 4. 系统更新状态为 PENDING_AUDIT |
|          | 5. 系统向管理员发送待审核通知 |

### UC-06 审核活动

| 项目 | 内容 |
|------|------|
| 用例名称 | 审核活动 |
| 参与者 | 管理员 |
| 前置条件 | 活动状态为 PENDING_AUDIT(1)，当前用户角色为管理员(2) |
| 后置条件 | 活动状态变为 PUBLISHED(2) 或 REJECTED(6) |
| 基本流程 | 1. 管理员在审核列表中查看待审核活动 |
|          | 2. 点击查看活动详细信息 |
|          | 3. 管理员选择"通过"或"驳回" |
|          | 4a. 通过：状态改为 PUBLISHED，通知组织者发布成功 |
|          | 4b. 驳回：填写驳回原因，状态改为 REJECTED，通知组织者 |
|          | 5. 系统记录审核人(auditBy)和审核时间(auditTime) |
