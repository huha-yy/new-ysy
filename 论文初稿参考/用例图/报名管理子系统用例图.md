# 报名管理子系统 — 用例图

## 参与者（Actor）

| 参与者 | 说明 |
|--------|------|
| 用户（User） | 已登录注册用户，提交和管理自己的报名 |
| 组织者（Organizer） | 活动创建者，审核报名申请 |

## 用例清单

| 编号 | 用例名称 | 参与者 | 关系 | 说明 |
|------|---------|--------|------|------|
| UC-01 | 提交报名申请 | 用户 | — | 填写紧急联系人等信息提交报名 |
| UC-02 | 进入候补队列 | 用户 | «extend» ← UC-01 | 名额已满时自动进入候补 |
| UC-03 | 查看我的报名 | 用户 | — | 查看所有报名记录及状态 |
| UC-04 | 取消报名 | 用户 | — | 取消待审核/已通过/候补的报名 |
| UC-05 | 审核报名 | 组织者 | — | 查看报名详情并通过或驳回 |
| UC-06 | 批量通过报名 | 组织者 | «extend» ← UC-05 | 一键通过所有待审核报名 |
| UC-07 | 驳回报名 | 组织者 | «extend» ← UC-05 | 填写驳回原因并拒绝报名 |

## 关键用例描述

### UC-01 提交报名申请

| 项目 | 内容 |
|------|------|
| 参与者 | 用户 |
| 前置条件 | 已登录，活动已发布或进行中，未过报名截止时间，未重复报名 |
| 后置条件 | 生成报名记录（PENDING 或 WAITING），通知组织者 |
| 基本流程 | 1. 用户在活动详情页点击报名 → 2. 填写紧急联系人和电话 → 3. 勾选装备和健康确认 → 4. 系统校验并创建报名记录 |
| 异常流程 | 4a. 名额已满，自动进入候补队列 |

### UC-05 审核报名

| 项目 | 内容 |
|------|------|
| 参与者 | 组织者 |
| 前置条件 | 报名状态为 PENDING(0) 或 WAITING(3) |
| 后置条件 | 状态变为 APPROVED(1) 或 REJECTED(2)，通知用户 |
| 基本流程 | 1. 组织者查看报名列表 → 2. 查看用户报名详情 → 3. 通过或驳回 → 4. 系统更新状态、调整参与人数、通知用户 |
