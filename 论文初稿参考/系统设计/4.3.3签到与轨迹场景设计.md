# 4.3.3 签到与轨迹场景设计

### 1. 静态结构设计

签到与轨迹场景涉及签到记录实体类（CheckInRecord）、轨迹记录实体类（TrackRecord）、预警事件实体类（AlertEvent）、检查点实体类（Checkpoint）四个核心实体，类图如图4-4所示。

**实体类说明**：

**签到记录实体类（CheckInRecord）**：存储签到记录信息，包括签到ID、用户ID、活动ID、签到点ID、签到时间、用户签到时的纬度、用户签到时的经度、与签到点的距离、签到状态等属性。

**轨迹记录实体类（TrackRecord）**：存储轨迹记录信息，包括轨迹ID、用户ID、活动ID、纬度、经度、海拔、定位精度、移动速度、记录时间等属性。

**预警事件实体类（AlertEvent）**：存储预警事件信息，包括预警ID、用户ID、活动ID、预警类型、预警级别、预警时的纬度、预警时的经度、预警描述、处理状态、创建时间等属性。

**检查点实体类（Checkpoint）**：存储签到检查点信息，包括检查点ID、活动ID、检查点名称、纬度、经度、有效半径、预计到达时间、排序序号等属性。

**类关系说明**：一个用户实体类（User）可以产生多条签到记录实体类（CheckInRecord）和多条轨迹记录实体类（TrackRecord），每个签到记录实体类（CheckInRecord）关联一个检查点实体类（Checkpoint），轨迹记录实体类（TrackRecord）上报后可能触发预警事件实体类（AlertEvent）。

### 2. 动态行为设计

**（1）时序图描述**

GPS签到的时序流程如下：用户在前端点击签到按钮，React组件调用浏览器Geolocation API获取当前GPS位置；获取位置后，前端向Controller发送POST请求，请求中携带JWT Token和签到数据；Controller进行JWT认证和参数校验后，调用Service层的performCheckIn方法；Service层首先通过Mapper校验用户的报名状态是否为已通过，活动状态是否为进行中；校验通过后，Service层获取签到点的坐标和有效半径；然后计算用户当前位置与签到点的距离，判断是否在有效半径（默认100米）内；若在有效范围内，Service层根据签到时间判断是否迟到，构建CheckInRecord对象，通过Mapper将签到记录插入MySQL数据库；最后返回签到结果给前端，前端显示签到成功提示。

**（2）轨迹上报与预警检测**

轨迹上报采用批量上传机制，前端每隔一定时间间隔收集用户的GPS位置数据，批量发送到后端。后端接收轨迹数据后，逐条存储到TrackRecord表，同时取最后一条轨迹数据触发预警检测。预警检测逻辑为：获取活动关联的路线的所有路点，计算用户当前位置与所有路点的距离，找到最近的路点距离；若距离超过严重偏离阈值（默认500米），创建严重偏离预警；若距离超过普通偏离阈值（默认200米），创建路线偏离预警。同一用户同一活动同一类型的未处理预警不重复创建。

**（3）定时任务预警**

系统通过定时任务实现超时未签到和失联检测。每5分钟执行一次检测任务：遍历所有进行中的活动，对每个有预计到达时间的签到点，检查已通过报名的用户是否已签到，若超过预计时间加超时阈值（默认30分钟）未签到，则创建超时未签到预警；同时查询每个参与者最后一条轨迹的记录时间，若超过失联阈值（默认30分钟）未上报轨迹，则创建失联预警。

### 3. 接口设计

签到与轨迹场景涉及的主要接口如下表所示：

| 接口名称 | 接口描述 | 使用说明 | 使用举例 |
| :--- | :--- | :--- | :--- |
| performCheckIn | 用户到达签到点后提交GPS位置完成签到，系统验证位置有效性 | 请求方式为POST，路径为/api/checkin，需携带JWT Token认证 | POST /api/checkin，请求体包含activityId、checkpointId、latitude、longitude字段 |
| uploadTracks | 用户行进过程中批量上报GPS轨迹数据，系统存储并触发偏离检测 | 请求方式为POST，路径为/api/checkin/tracks，需携带JWT Token认证 | POST /api/checkin/tracks，请求体包含tracks数组，每条记录包含latitude、longitude、recordTime等字段 |
| getParticipantsCheckIn | 组织者实时查看所有参与者的签到进度和位置信息 | 请求方式为GET，路径为/api/activities/{activityId}/participants-checkin，仅活动组织者可调用 | GET /api/activities/1/participants-checkin |
| getAlertList | 组织者查询活动相关的预警事件，支持按状态筛选 | 请求方式为GET，路径为/api/alerts，仅活动组织者可调用 | GET /api/alerts?activityId=1&status=0 |
