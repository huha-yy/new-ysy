5.2.1 用户管理
用户管理模块是本系统实现用户身份认证和基础信息管理的核心功能模块，目的在于为用户提供安全可靠的账号注册、登录和档案管理功能，为系统其他业务模块提供用户身份基础支撑。该模块融合了用户注册、用户登录、用户信息查询、用户档案管理等功能，通过完善的认证体系和档案管理机制全面保障用户数据安全。用户可通过用户名、手机号或邮箱注册账号，系统自动进行唯一性校验并采用BCrypt加密算法保护密码安全。注册成功后自动创建用户档案，包含个人资料、健康信息、紧急联系人等详细数据。用户登录时系统校验用户名密码和账号状态，生成JWT Token用于后续请求认证。用户可查看和更新个人档案信息，包括昵称、头像、真实姓名、性别、出生日期、徒步经验等级、健康状况、病史过敏史、紧急联系人、常用装备清单、活动偏好等。系统通过角色权限机制控制用户操作权限，普通用户可参与活动、组织者可发布活动、管理员可管理审核。该模块的实现构建了完善的用户管理体系，通过安全的认证机制和完整的档案管理为系统各项业务提供用户身份保障，是户外徒步活动管理系统的重要基础。

② 实现原理
用户管理模块基于标准的前后端分离架构，整体采用SpringBoot + React + MyBatis-Plus三层架构模式，通过"表现层（Controller）"、"业务逻辑层（Service）"与"数据访问层（Mapper）"的合理分工，保障模块功能的稳定、高效与易维护性。

表现层（Controller）：主要负责接收用户前端页面发起的请求，如用户注册、用户登录、获取用户信息、获取用户档案、更新用户档案等，并将参数传入业务逻辑层处理。页面展示上支持表单输入、密码显示隐藏切换、头像上传预览、表单验证、成功提示等交互，增强用户体验。该层使用SpringBoot的@RestController注解，配合Swagger3的@Operation注解生成API文档。权限控制通过@SecurityRequirement注解实现，确保用户注册和登录为公开接口，获取和更新用户信息必须登录。

业务逻辑层（Service）：该层实现用户数据管理的核心逻辑，包括用户唯一性校验、密码加密、用户创建、用户档案创建、用户登录验证、账号状态校验、JWT Token生成、用户信息查询、用户档案查询、用户档案更新等。在用户注册时，系统执行多重校验：用户名唯一性校验、手机号唯一性校验（如提供）、邮箱唯一性校验（如提供）。校验通过后使用BCrypt加密算法对密码进行加密存储，创建用户记录包含用户名、加密密码、手机号、邮箱、角色（默认为普通用户）、状态（默认为正常）等字段。同时创建用户档案记录，默认经验等级为新手。最后生成JWT Token并返回，包含用户ID、用户名、角色等信息。用户登录时系统查询用户记录，校验用户存在性和账号状态，使用BCrypt验证密码，更新最后登录时间并生成JWT Token。获取用户信息时查询用户基本信息并返回。获取用户档案时联合查询用户基本信息和档案信息，组装成完整的用户档案数据返回，包含个人资料、健康信息、紧急联系人、偏好设置等。更新用户档案时校验手机号和邮箱的唯一性（如修改），更新用户基本信息（昵称、头像、手机号、邮箱），更新或创建用户档案记录（真实姓名、性别、出生日期、经验等级、健康状况、病史过敏史、紧急联系人、常用装备清单、偏好强度、偏好里程、偏好地区、个人简介等）。

数据访问层（Mapper）：通过MyBatis-Plus的封装接口，完成对user和user_profile等数据表的增删查改操作，简化SQL管理。同时支持Lambda表达式实现复杂条件的查询，如"根据用户名查询用户"、"根据用户ID查询用户档案"、"查询用户信息是否存在"等功能。MyBatis-Plus的LambdaQueryWrapper实现条件构造。

用户注册与认证机制：系统采用用户名、手机号、邮箱作为用户标识，支持三种方式注册。注册时自动进行唯一性校验，确保用户名、手机号、邮箱不重复。密码使用BCrypt加密算法加密存储，该算法内置盐值，相同密码每次加密结果不同，有效防止彩虹表攻击。用户登录成功后生成JWT（JSON Web Token）用于后续请求的身份认证，Token包含用户ID、用户名、角色等信息，有效期为7天。前端将Token存储在本地，后续每次请求通过Authorization头携带Token，后端通过JWT拦截器解析Token验证用户身份。系统支持角色权限控制，角色类型包括普通用户（0）、组织者（1）、管理员（2），不同角色拥有不同操作权限，普通用户可报名参与活动，组织者可发布管理活动，管理员可审核活动、管理用户等。

用户档案管理机制：系统将用户信息分为基础信息和档案信息两部分，基础信息存储在user表，包含用户名、密码、昵称、头像、手机号、邮箱、角色、状态、最后登录时间等；档案信息存储在user_profile表，包含真实姓名、性别、出生日期、徒步经验等级（0新手、1初级、2中级、3高级、4专业）、健康状况描述、病史过敏史、紧急联系人姓名、紧急联系人电话、常用装备清单、偏好强度（1低、2中、3高）、偏好里程（1短、2中、3长）、偏好地区（多个逗号分隔）、个人简介等。这种分离设计既保障了基础信息的访问效率，又支持档案信息的灵活扩展。用户档案支持创建、查询、更新操作，注册时自动创建空档案，用户可在个人中心完善档案信息，组织者审核活动报名时可查看用户档案以判断是否符合活动要求（如经验等级、健康状况等）。偏好设置（偏好强度、偏好里程、偏好地区）用于为用户推荐合适的活动。

数据存储设计：系统采用MySQL数据库存储用户相关信息，user表存储用户基本账户信息，包含id、用户名、密码、昵称、头像、手机号、邮箱、角色、状态、最后登录时间、创建时间、更新时间等字段。user_profile表存储用户详细档案信息，包含id、用户ID、真实姓名、性别、出生日期、经验等级、健康状况、病史过敏史、紧急联系人姓名、紧急联系人电话、常用装备清单、偏好强度、偏好里程、偏好地区、个人简介、创建者ID、更新者ID、创建时间、更新时间等字段。user表与user_profile表通过user_id字段一对一关联。密码字段使用BCrypt加密存储，角色字段控制用户权限，状态字段控制账号是否可用（1正常、0禁用）。档案信息支持可选字段，用户可逐步完善个人信息。
